# Фінальне домашнє завдання. Міграція через fan-out і план впровадження

> Курс «Агентна розробка з ШІ» · до лекції 5 «Масштаб і production»
> **Термін:** 2 тижні після лекції 5
> **Розбір:** асинхронний або на окремій короткій зустрічі
> **Інструмент:** будь-який агентний. Приклади наведено для Claude Code, відповідники — у розділі «Якщо у вас інший інструмент».

## Мета

Застосувати все з курсу на задачі «справжнього» масштабу і підготувати пропозицію для своєї команди:
1. Провести масову механічну зміну за схемою **пілот → playbook → масштаб**.
2. Оцінити бюджет **до** запуску і порівняти з фактом.
3. Скласти план впровадження агентних практик на 30 днів.

## Частина 1. Міграція

### Крок 1. Оберіть задачу

Механічна однотипна зміна у **10+ файлах**, наприклад:
- перехід на новий логер чи API клієнта;
- заміна застарілого методу;
- додавання типів або docstrings за шаблоном;
- переведення тестів на новий фреймворк асертів.

Задачі мають бути **незалежними**: зміна одного файлу не повинна вимагати рішень у іншому. Паралельно читати агенти вміють добре, а паралельно писати пов'язаний код — погано.

### Крок 2. Пілот

1. Виконайте зміну на **3–5 файлах** разом з агентом.
2. Запишіть, що спрацювало, а що довелося виправляти.
3. Заміряйте витрати на один файл.

### Крок 3. Playbook

Оформіть результат пілоту як промпт або skill: що змінювати, як перевірити, що робити з винятками.

### Крок 4. Бюджет до запуску

```
бюджет ≈ середня вартість пілотного файлу × кількість файлів × 1,3–1,5
```

Запишіть оцінку **до** запуску.

### Крок 5. Масштаб

Варіант А — `/batch` у Claude Code: розбиває зміну на одиниці, кожну виконує в окремому worktree і відкриває PR.

Варіант Б — скрипт у headless-режимі:

```bash
for file in $(cat files.txt); do
  claude --bare -p "Migrate $file to the new logger API and commit. Reply OK or FAIL." \
    --allowedTools "Read,Edit,Bash(git add *),Bash(git commit *)" \
    --permission-mode dontAsk \
    --max-turns 20
done
```

Перед запуском дайте відповідь на п'ять питань:
1. Чи знає агент, як виглядає «готово»?
2. Чи може він перевірити свою роботу?
3. Що йому дозволено?
4. Що його зупинить (`--max-turns`, ліміт витрат)?
5. Куди йде результат і хто його затверджує?

### Крок 6. Перевірка

Тести + вибіркове рев'ю щонайменше кількох змінених файлів. Запишіть фактичні витрати.

## Частина 2. План впровадження на 30 днів

Шаблон:

```markdown
# Впровадження агентної розробки в команді <назва>

## Пілотна група
<3–5 людей, хто і чому>

## План
| Тиждень | Що робимо | Результат |
|---|---|---|
| 1 | Спільний файл інструкцій, базові hooks | Базові метрики |
| 2 | Skills для 2–3 найчастіших процесів, рев'ю PR у CI | Перші результати |
| 3 | Командний плагін або спільна конфігурація, розширення | Відтворюваний setup |
| 4 | Ретроспектива, порівняння метрик, рішення про масштаб | План наступного етапу |

## Метрики
- Cycle time (від початку задачі до merge)
- Частка відхилених або сильно переписаних PR
- Вартість на задачу
- Частка розробників, які користуються регулярно

## Бюджет
<оцінка на місяць і ліміти витрат>

## Ризики і як їх знижуємо
- <бездумний merge коду агента → обов'язкове рев'ю, quality gates>
- <витік секретів → deny-правила, hooks>
- ...

## Хто відповідає
<за файл інструкцій, плагін/конфігурацію, метрики>
```

## Що здати

1. PR (або кілька) з міграцією.
2. `PLAYBOOK.md` — промпт або skill з пілоту.
3. Звіт за шаблоном:

```markdown
## Фінальне ДЗ — <ім'я>

**Інструмент:** <назва>   **Задача:** <одне речення>   **Файлів:** <N>

| | Оцінка | Факт |
|---|---|---|
| Витрати | | |
| Час | | |
| Файлів без ручних виправлень | | |

**Що пішло не так і чому:** <перелік>
**Порівняння з ДЗ 1:** <як змінилися мої витрати і підхід за курс>
```

4. План впровадження за шаблоном вище.

## Критерії оцінювання

| Зараховано | Добре | Відмінно |
|---|---|---|
| Міграція виконана | Є пілот і playbook | Бюджет оцінено до запуску і порівняно з фактом |

## Якщо у вас інший інструмент

| | Паралельні агенти | Headless | Пакування для команди | CI-агент |
|---|---|---|---|---|
| **Claude Code** | `claude -w`, `/batch` | `claude -p` | Plugins + marketplace | GitHub Actions (`claude-code-action`) |
| **Cursor** | Паралельні агенти з worktree, cloud agents | Cursor CLI | Plugins + Cursor Marketplace | Cloud agents |
| **GitHub Copilot** | Кілька задач для coding agent | Copilot CLI | Plugins | Copilot coding agent |
| **OpenAI Codex** | Subagents, cloud tasks | `codex exec` | Plugins | Codex у GitHub / cloud |
| **Gemini CLI** | Worktrees, subagents (перевірте) | `gemini -p` | Extensions | GitHub Action (перевірте) |
| **Z.ai ZCode** | Паралельні агенти, worktrees | Agent CLI `zcode` (перевірте) | Plugins + marketplace | Перевірте |

Якщо паралельного запуску немає, виконуйте файли послідовно в окремих сесіях: схема «пілот → playbook → масштаб» і бюджет працюють так само.

## Поради

- Не запускайте міграцію на всі файли, поки пілот не пройшов без ручних виправлень хоча б на 3 файлах.
- Гілки та PR — обов'язково. Жодних змін напряму в `main`.
- Якщо PR конфліктують між собою, задачі були недостатньо незалежними. Це теж цінний висновок для звіту.
